# Telegram-бот с оплатой через Telegram Stars ⭐️

Готовый бот на Node.js ([Telegraf](https://telegraf.js.org/)), который показывает каталог
товаров и принимает оплату во внутренней валюте Telegram — **Stars**. Никакого
внешнего платёжного провайдера (Stripe, ЮKassa и т.п.) не требуется — Stars
обрабатываются напрямую серверами Telegram.

## Что уже сделано в коде

- `/start` — показывает предложение с кнопкой покупки.
- Нажатие на кнопку → бот отправляет счёт (`sendInvoice`) в звёздах.
- Обработка `pre_checkout_query` — обязательное подтверждение перед списанием денег.
- Обработка `successful_payment` — бот выдаёт промокод и логирует оплату в консоль.
- `/refund <charge_id>` — команда владельца бота для возврата звёзд покупателю.
- Товар, цена и все тексты настраиваются через переменные окружения — см. раздел ниже.

## Шаг 1. Получить токен бота

Вы уже создали бота через [@BotFather](https://t.me/BotFather) — значит у вас есть токен вида
`123456789:AAExampleToken...`. Если токена нет под рукой:

1. Откройте чат с `@BotFather`.
2. Отправьте `/mybots` → выберите вашего бота → **API Token**.

## Шаг 2. Установить зависимости

```bash
cd telegram-stars-bot
npm install
```

## Шаг 3. Настроить переменные окружения

```bash
cp .env.example .env
```

Откройте `.env` и впишите минимум:

```
BOT_TOKEN=токен_от_botfather
ADMIN_ID=ваш_telegram_id
PROMO_CODE=ваш_промокод
```

`ADMIN_ID` нужен только для команды `/refund` (узнать свой id можно у бота
[@userinfobot](https://t.me/userinfobot)). Если возвраты не нужны — можно оставить пустым.

## Шаг 4. Запустить бота

```bash
npm start
```

В консоли появится `Бот запущен и слушает Telegram (long polling)`. Идите в Telegram,
напишите боту `/start` — увидите предложение с кнопкой покупки.

## Шаг 5. Проверить оплату

1. Нажмите кнопку покупки — придёт счёт (invoice) с кнопкой «Оплатить».
2. **Важно:** в обычном (не тестовом) режиме Stars списываются по-настоящему —
   у пользователя должен быть баланс звёзд (их можно купить прямо в Telegram).
   Комиссию за Stars-платежи Telegram не берёт, но при выводе денег на реальные
   средства (не звёзды) берётся комиссия — см. официальную документацию.
3. После оплаты бот пришлёт промокод, а в консоли появится лог с
   `telegram_payment_charge_id` — он нужен, если захотите сделать возврат.

## Шаг 6. (Опционально) Сделать возврат

```
/refund <telegram_payment_charge_id>
```

Команда доступна только пользователю с `ADMIN_ID` и работает только для оплат,
совершённых после запуска текущего процесса бота (данные о покупках хранятся
в памяти — см. раздел «Что доработать для продакшена»).

## Шаг 7. (Опционально) Оплата картой и криптой через Cryptomus

Помимо Stars бот умеет принимать оплату картой (кроме РФ — у большинства
эквайеров, работающих с иностранными мерчантами, российские карты просто не
проходят) и криптовалютой через [Cryptomus](https://cryptomus.com/) — это
отдельный сервис, не связанный с Telegram Payments.

### 7.1. Завести аккаунт на Cryptomus

1. Зарегистрируйтесь на https://cryptomus.com/
2. В личном кабинете создайте мерчанта (Merchant) — получите **Merchant UUID**.
3. В настройках мерчанта создайте **API key** (Payment API key).
4. Для приёма именно карт может потребоваться пройти верификацию бизнеса —
   уточняйте актуальные требования в поддержке Cryptomus, для крипты обычно
   верификация не нужна.

### 7.2. Сделать сервис на Railway публичным

Cryptomus присылает уведомление об оплате через вебхук — это HTTP-запрос,
который должен долететь до вашего бота, значит сервису нужен публичный адрес:

1. В сервисе на Railway откройте **Settings → Networking**.
2. Нажмите **Generate Domain** — Railway выдаст адрес вида
   `https://your-app.up.railway.app`.

### 7.3. Добавить переменные

В Railway → Variables добавьте:

| Переменная | Значение |
|---|---|
| `CRYPTOMUS_MERCHANT_ID` | Merchant UUID из кабинета Cryptomus |
| `CRYPTOMUS_API_KEY` | API key из кабинета Cryptomus |
| `PRICE_USD` | цена товара в долларах, например `5` |
| `PUBLIC_URL` | публичный домен из шага 7.2, например `https://your-app.up.railway.app` |

Как только все четыре переменные заданы, в боте на `/start` появится вторая
кнопка — «💳 Карта / Крипта». Если хоть одной переменной нет — кнопка просто
не показывается, а Stars продолжают работать как обычно.

### 7.4. Как это работает

1. Покупатель жмёт «💳 Карта / Крипта» → бот через API Cryptomus создаёт счёт
   и присылает ссылку на оплату.
2. Покупатель оплачивает на странице Cryptomus (там уже сам Cryptomus
   показывает выбор — карта или конкретная криптовалюта).
3. Cryptomus шлёт на `PUBLIC_URL/cryptomus/webhook` уведомление об оплате.
4. Бот проверяет подпись запроса и присылает покупателю промокод — точно так
   же, как при оплате Stars.

Обработчик подписи вебхука реализован в `src/cryptomus.js` по стандартной
для Cryptomus схеме (md5 от base64 тела запроса + API key). Если Cryptomus
поменяет формат — пришлите мне пример реального вебхука из логов, поправим.

## Как менять товар, цену и все тексты — без кода, через Variables на Railway

Бот продаёт один товар (промокод), и почти всё про него настраивается
переменными окружения — зайдите в Railway → Variables и меняйте:

| Переменная | За что отвечает | Пример |
|---|---|---|
| `PROMO_CODE` | сам промокод, который получает покупатель | `OCTOBER25` |
| `PRICE_STARS` | цена в Stars | `500` |
| `PRODUCT_NAME_RU` / `PRODUCT_NAME_EN` | название товара | `журнал «Хакер»` |
| `SUBSCRIPTION_PERIOD_RU` / `SUBSCRIPTION_PERIOD_EN` | срок подписки | `1 месяц` |
| `OFFER_TEXT_RU` / `OFFER_TEXT_EN` | текст на `/start` | см. ниже |
| `INVOICE_TITLE_RU` / `INVOICE_TITLE_EN` | заголовок счёта на оплату | см. ниже |
| `INVOICE_DESCRIPTION_RU` / `INVOICE_DESCRIPTION_EN` | описание в счёте | см. ниже |
| `PAY_LABEL_RU` / `PAY_LABEL_EN` | строка с ценой в счёте | см. ниже |
| `THANKS_TEXT_RU` / `THANKS_TEXT_EN` | сообщение после оплаты (с кодом) | см. ниже |
| `BUY_BUTTON_RU` / `BUY_BUTTON_EN` | текст кнопки покупки за Stars | `GET LINK!` |
| `SOLD_OUT_TEXT_RU` / `SOLD_OUT_TEXT_EN` | сообщение, если промокод не задан | см. ниже |
| `CARD_BUTTON_RU` / `CARD_BUTTON_EN` | текст кнопки оплаты картой/крипто | `💳 Карта / Крипта — ${priceUsd}` |
| `PAY_LINK_TEXT_RU` / `PAY_LINK_TEXT_EN` | текст перед ссылкой на оплату | см. ниже |
| `PAY_LINK_BUTTON_RU` / `PAY_LINK_BUTTON_EN` | текст кнопки-ссылки на оплату | `Оплатить` |
| `CARD_PAYMENT_UNAVAILABLE_RU` / `_EN` | сообщение при ошибке Cryptomus | см. ниже |

Если переменную не задать — используется текст по умолчанию (бот не сломается).

### Как переписать текст целиком

В `OFFER_TEXT_*`, `INVOICE_TITLE_*`, `INVOICE_DESCRIPTION_*`, `PAY_LABEL_*` и
`THANKS_TEXT_*` можно вставлять плейсхолдеры — бот сам подставит туда значения:

- `{product}` → значение `PRODUCT_NAME_RU`/`EN`
- `{period}` → значение `SUBSCRIPTION_PERIOD_RU`/`EN`
- `{price}` → значение `PRICE_STARS`
- `{priceUsd}` → значение `PRICE_USD` (доступен только в `CARD_BUTTON_*`)
- `{code}` → сам промокод (доступен только в `THANKS_TEXT_*`)

Например, чтобы полностью переписать сообщение на `/start`, задайте переменную
`OFFER_TEXT_RU` со значением:

```
🔥 Специальное предложение!
Промокод на {product} сроком {period} всего за {price} звёзд.
```

Бот подставит туда реальные название, срок и цену — сама фраза при этом
целиком ваша, редактировать код не нужно.

Изменения применяются после сохранения переменной — Railway сам
пересоберёт и перезапустит бота.

## Как задеплоить, чтобы бот работал 24/7

Сейчас бот работает через long polling (опрашивает Telegram сам) — этого
достаточно для большинства случаев. Варианты хостинга:

- **VPS** (например, обычный Linux-сервер): скопировать папку, `npm install`,
  запустить через `pm2 start index.js --name stars-bot` или через systemd-сервис,
  чтобы бот перезапускался при падении/перезагрузке сервера.
- **Railway / Render / Fly.io** — задеплоить как обычное Node.js-приложение,
  указать переменные окружения `BOT_TOKEN` и `ADMIN_ID` в настройках сервиса.
- **Docker**: добавить простой `Dockerfile` (`FROM node:20-alpine`, `COPY`,
  `npm ci --omit=dev`, `CMD ["node", "index.js"]`).

Держать `.env` и токен в секрете — не коммитьте `.env` в git (он уже в `.gitignore`).

## Что доработать для продакшена

- Заменить `Map` в `src/bot.js` (переменная `purchases`) на настоящую БД
  (Postgres/SQLite/Redis), чтобы история покупок не терялась при перезапуске.
- При большом трафике — перейти с long polling на webhook
  (`bot.launch({ webhook: { domain, port } })`, см. документацию Telegraf).
